# Test-only dependencies. Runtime dependencies stay in each service's own
# requirements.txt; nothing here is installed into a service image.
#
#   python3 -m venv .venv
#   .venv/bin/pip install -r requirements-dev.txt
#
# Versions are pinned because the ML-KEM known-answer tests call kyber-py's
# internal seeded functions (_keygen_internal, _encaps_internal). Those are the
# only way to drive the deterministic algorithms ACVP specifies, and they are
# private API, so an unpinned upgrade can break the suite without warning.

# tests/crypto and tests/reliability import gateway/app and cloud/app
# in-process, so they need both services' runtime dependencies (fastapi,
# cryptography, prometheus-client, ...). These used to be assumed present
# in a shared venv; a clean install from this file alone could not import
# them. Including the service files keeps the pins in one place.
-r gateway/requirements.txt
-r cloud/requirements.txt
