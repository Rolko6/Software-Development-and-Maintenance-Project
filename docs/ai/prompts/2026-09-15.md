### Output and disposition

Added `tests/crypto/` (ML-KEM conformance against NIST ACVP vectors and FIPS 203
behaviour), `tests/protected_path/` (gateway integration contract, skipped until
`gateway/app/kem.py` exists, plus a source scan for classical key agreement),
`tests/vectors/` (the ACVP subset and its extraction script), `tests/support.py`,
`tests/conftest.py`, root `pytest.ini`, `requirements-dev.txt`,
[docs/testing/ml-kem-verification.md](../../testing/ml-kem-verification.md), and
[a validation record](../../validation/2026-09-15-ml-kem-tests.md).

The assistant's substantive answer to the question as asked: no test can show
that ML-KEM is post-quantum. Quantum resistance is a property of the Module-LWE
problem and of NIST's cryptanalysis, inherited by a deployment that computes the
standardised algorithm. The suite is built to establish that inheritance —
conformance to published vectors, required behaviour, and actual use on the
protected link — and the verification document states plainly which claims it
does not support.

The interface in `tests/protected_path/test_protected_path_contract.py` is a
proposal from the tests, not a group decision. `gateway/app/kem.py` was not
created; work package 3 remains unstarted.

### Verification and remaining uncertainty

See the [validation record](../../validation/2026-09-15-ml-kem-tests.md): 79
passed, 1 skipped; two injected defects confirmed the suite fails for the right
reasons; `git diff --check` clean. Context7 has no `kyber-py` entry, so the
library's installed source and metadata were read directly. Side-channel
behaviour was not measured, and the implementation under test states it is not
suitable for cryptographic use. Human review of these tests is not recorded.
